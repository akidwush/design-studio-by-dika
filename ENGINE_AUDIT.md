## Integration boundary

One Kotlin document model owns ordering, stable IDs, layer metadata, bitmap pixels and vector source/shape parameters. One compositor delegates SVG rendering to AndroidSVG and bitmap drawing to Android Canvas. CiDrawing constructs stroke paths; the adapter configures a single smooth round brush (matching upstream smoothing settings) and Android PorterDuff CLEAR for erasing. No new fitting, brush synthesis, SVG parser, Bézier algorithm or boolean engine was written. The XML pull parser in SvgGuard is an allowlist/security validator, not an SVG renderer.

All Java source files are retained unmodified to preserve their internal dependencies and useful upstream functionality. Their original Gradle configuration and sample applications/assets are not included. `tools/verify_vendored.py` checks source/resource provenance using recorded SHA-256 hashes. No icons, fonts, brush presets or upstream sample assets are bundled. UI uses platform widgets and fonts.

Editable native vector layers contain one rectangle, circle, ellipse, line or predefined cubic path each. Their fill, stroke and transform remain vector parameters. Imported SVG is a preserved XML resource; it can be moved/scaled/rotated as a layer, but its nodes/colors are not editable. Unsupported SVG is rejected explicitly. SVG export rejects a document containing any raster/image layer, even hidden layers, to avoid silently losing content. PNG export composites a snapshot without changing the original document.

## Dependency and asset audit scope

APK runtime: vendored CiDrawing/AndroidSVG (Apache-2.0), Kotlin stdlib 2.1.20 and JetBrains annotations (Apache-2.0), plus Android OS APIs. Neither engine source tree imports another third-party library. Original copyright headers, upstream LICENSE texts, and notices are retained and bundled. No GPL/AGPL application code is integrated.

Build/test-only dependencies (AGP, Gradle, Kotlin tooling, JUnit, Robolectric and their transitives) are not packaged as application engines. The resolved runtime dependency tree and POM license records are captured in `audit/`; test-only dependencies are listed separately and must be re-audited if ever shipped. This is an engineering license review, not a claim that every optional upstream asset/submodule is cleared for reuse.
